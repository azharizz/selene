# Selene: Vega OS to Fire OS migration report

Branch: `migrate-to-fireos` (uncommitted). Source of truth for UI and behaviour: `native-vega-tv`.
Date: 2026-10-09.

## Summary

`fireos/` is a new React Native Expo app for Fire TV and Android TV:

- Built on Expo SDK 57 with `react-native-tvos` 0.86.3-0.
- No WebView anywhere.
- The UI code is the native-vega-tv code, ported almost line for line.
- Films play through `expo-video`, which uses ExoPlayer.
- Built as a debug APK and run on an Android TV emulator (1080p, API 31). Every screen was compared against the Vega and web references.

The Vega app is untouched: `src/`, `manifest.toml` and `package.json` at the selene root. Root `npm run typecheck`, `npx jest` (4/4) and `npm test` (127/127) pass.

## Architecture

| Concern | Vega (native-vega-tv) | Fire OS (fireos/) |
|---|---|---|
| Runtime | Kepler React Native | Expo SDK 57 + `react-native-tvos` (`@react-native-tvos/config-tv`, `isTV: true`) |
| Layout | 640x360 dp window at density 2; CSS px / 2 | Same 640x360 canvas, scaled to the window (`src/App.tsx`, `src/canvas.ts`). On a 1080p TV (960x540 dp) the scale is 1.5, so every CSS length lands at `css * width / 1280`, matching Vega |
| Video | Kepler W3C VideoPlayer + MSE (30s lead) + `KeplerVideoSurfaceView` | `expo-video` `createVideoPlayer` + `VideoView` (`surfaceType="textureView"`, so the video follows the canvas transform). ExoPlayer streams the progressive MP4 from the relay directly; no MSE needed |
| `NativeFilm` API (`src/media.ts`) | MSE wrapper with HTML-like events | Same surface (play/pause/currentTime/ended + events), mapped from expo-video's statusChange, playingChange, timeUpdate and playToEnd |
| Remote media keys (`src/OwnPlayerSession.ts`) | Kepler PlayerSession | `TVEventHandler`: playPause / play / pause / fastForward (+10s) / rewind (-10s) |
| Storage | Vega async-storage port | `@react-native-async-storage/async-storage` |
| Accessibility settings (`src/Accessibility.ts`) | Kepler a11y settings module | RN `AccessibilityInfo` (screen reader) |
| SVG | `@amazon-devices/react-native-svg` | `react-native-svg` |
| Landing (`src/Companion.tsx`) | Discovers other apps' playback via Media Controls | Same screen and motion; always reports "Playback discovery is unavailable. Watch a demo instead." (see gaps) |
| Unchanged files | — | `Player.tsx` (import swaps + `VideoView`), `Moment.tsx`, `Motion.tsx`, `Visual.tsx`, `ui.tsx`, `api.ts` |

Manifest (generated by the config plugins):

- LEANBACK_LAUNCHER, `touchscreen required=false`, TV banner.
- `usesCleartextTraffic=true`, because the relay serves plain HTTP on `127.0.0.1:4519`.

## Build and run

The toolchain is installed with Homebrew:

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
export PATH=$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH
```

Emulator (AVD `selene_tv`, tv_1080p, `system-images;android-31;android-tv;arm64-v8a`):

```bash
emulator -avd selene_tv            # add -no-window -gpu swiftshader_indirect for headless
```

Build, install, run:

```bash
cd fireos
npm install --legacy-peer-deps     # react-native-tvos alias trips npm peer checks
EXPO_TV=1 npx expo prebuild -p android --clean
(cd android && ./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a)
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb reverse tcp:4519 tcp:4519      # SELENE relay (start it from the selene root as usual)
adb reverse tcp:8081 tcp:8081      # Metro, debug builds only
EXPO_TV=1 npx expo start --port 8081
adb shell monkey -p com.selene.fireos -c android.intent.category.LEANBACK_LAUNCHER 1
```

Real Fire TV stick:

1. Turn on Developer options and ADB debugging.
2. Run `adb connect <tv-ip>:5555`.
3. Build with `-PreactNativeArchitectures=armeabi-v7a,arm64-v8a`.
4. Point `src/config.json` `appUrl` at the relay's LAN address, because `adb reverse` only covers USB/emulator.

Real Fire OS without hardware (Amazon's official route): **Live Device Interaction** in the Developer Console runs real Fire TV devices with Fire OS 8/14/16 in Amazon's device farm ([docs](https://developer.amazon.com/docs/app-testing/live-device-interaction-virtual.html)). There is no downloadable Fire OS emulator.

1. From the selene root, start the relay as usual.
2. Run `fireos/cloud-apk.sh`. It opens a temporary Cloudflare tunnel to the relay, bakes the tunnel URL into a release APK (armeabi-v7a + arm64-v8a), and prints the APK path.
3. In the console, go to Tools & Services → Appstore Quality Central → Virtual devices → Get Started.
4. Pick a Fire TV device, then use Dashboard → App Upload to install the APK. The Remote tab gives you a D-pad.
5. Press Ctrl-C in the script's terminal when you're done. That closes the tunnel and restores `src/config.json`. The relay is public while the tunnel is open.

Checks:

```bash
cd fireos && npx tsc --noEmit -p . && npx eslint src App.tsx      # both clean
```

### Bug found and fixed

ExoPlayer sends `playingChange(false)` right after `playToEnd`, which marked the film as paused instead of ended. The Playback sheet then showed "Play" instead of "Replay". `media.ts` now ignores that trailing pause. It also ignores the empty player's `playToEnd` before a source has loaded.

### Gotchas hit during testing

- **Stale Metro cache:** Metro once kept serving an old `media.ts` to the device's (hermes) bundle URL after edits. If the app doesn't reflect a change, restart with `npx expo start --clear`.
- **Root `node_modules`:** the root `node_modules` was left over from the native-vega-tv install, which has no `@amazon-devices/webview`. This branch's master-based root source imports it, so root typecheck/jest failed until `npm ci` at the root. No tracked files changed. Switching back to native-vega-tv needs its own `npm ci` there.

## Known gaps

- **No playback discovery or CompanionMoment.** Fire OS gives a regular app no access to other apps' media sessions. The landing therefore always offers the demo/import path. Re-add it only if a notification-listener permission or a partner integration becomes available; this is marked with a `ponytail:` comment in `Companion.tsx`.
- **Voice / read-aloud** from the Vega a11y module is not wired. Only screen-reader state is read.
- **Emulator image is API 31.** There is no arm64 Android TV API 30 image for Apple Silicon. Fire OS 7/8 devices are API 28/30, and expo-video and react-native-tvos support both. Test on a real stick before shipping.
- **Debug build only.** It needs Metro. For a standalone APK use `cd fireos/android && ./gradlew assembleRelease` with a signing config.
- Import MP4 and credits were not exercised on Fire OS. The code is identical to Vega's.
